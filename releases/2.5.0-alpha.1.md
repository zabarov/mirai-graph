# Mirai 2.5.0-alpha.1

Status: local alpha candidate; not published

Mirai 2.5 adds Outcome Completion as an additive core extension. It checks
whether a useful result is supported by the required evidence instead of
treating retrieval, activity, tests or generated prose as completion.

## Included

- `@zabarov/mirai/outcome` CommonJS and ESM export;
- versioned contract, candidate, assessment and delivery schemas;
- deterministic evidence admission, status classification and digesting;
- pure operation catalog composed through existing Mirai Program `call` nodes;
- additive Task Plan outcome contract references;
- `mirai outcome validate|assess|explain|template propose` commands;
- positive, negative and replay fixtures;
- synthetic/shadow knowledge, Federation/project and AI Employee pilot slices;
- independent Python conformance extension prepared in a separate repository.

## Local Evidence

- 13 Outcome Completion tests pass, including 100-run digest determinism;
- all negative, CLI and synthetic pilot checks pass;
- independent Python checker passes 31 tests and validates seven Outcome
  artifacts against exact local revisions;
- the independent checker remains a local candidate, so its result is not yet
  eligible as a public release gate;
- internal security pre-review closed four findings; independent security
  review remains pending.

## Boundaries

- This alpha is not a stable release and has not been published.
- Retrieval evidence is input to assessment, not business acceptance.
- Candidate values, generated templates and delivery plans never authorize an
  effect, capability, approval or canonical write.
- Controlled synthetic/shadow pilots do not establish external product
  effectiveness or production readiness.
- Stable `2.5.0` requires independent conformance, security review,
  cross-platform clean-room checks, controlled product pilots and owner release
  approval.
